# كشيدة | غرفة الأخبار

أول مسار قابل للتجربة في منصة رصد متعددة الجهات. يضيف المحرر مصادر جهته، يفتح تيار Facebook أو X، ويفلتر المنشورات حسب المصدر والنص والصور والفيديو. الواجهة عربية، وتعرض وقت الرصد ووقت النشر بتوقيت القاهرة. اعتمدنا الرابط الذي أرسله الفريق مستودعًا للمنصة.

## جرّب المسار

1. افتح تيار «مزيد»، ثم اختر «صور». يظهر منشور البرنامج من «اليوم السابع». افتح تفاصيله لمراجعة توقيت النشر والرصد.
2. بدّل مساحة العمل إلى «رصد». ستجد برنامج اليوم نفسه مع خبر آخر خاص باختيارات رصد.
3. من «المصادر» أوقف «اليوم السابع» عند رصد. تختفي الصورة من تيارها وتبقى عند مزيد. يمكنك استئناف المصدر.
4. جرّب إضافة `https://x.com/Youm7` في إحدى الجهتين، ثم افتح X في تيارها. إعادة إدخال الرابط تعطي «متابَع بالفعل». رابط جروب غير معروف يدخل قائمة التحقق ويمكن إلغاء الطلب.
5. تعرض المعاينة مادة توضيحية من إعدادنا، بما فيها الصورة والفيديو. من حقول التفاصيل يمكن زيارة صفحة المصدر. عندما يحمل المنشور الحقيقي رابطه الأصلي يفتح الكارت ذلك الرابط.

## شغّل المشروع

يتطلب Node.js 24 وnpm. يعمل وضع التجربة بدون مفاتيح.

```sh
npm ci
npm run dev
```

افتح `http://localhost:3000`. تختار الجهة من أعلى الصفحة، ويحفظ المتصفح تغييرات متابعة المصادر. في الاستضافة التي تستخدم Supabase، يُستبدل اختيار الجهة التجريبي بتسجيل الدخول ومساحات العضوية المصرح بها.

```sh
npm test
npm run build
```

تختبر الحزمة قواعد الرؤية الفعلية في محرك PostgreSQL محلي عبر PGlite، والحجز والإيقاف والتكرار والفلاتر. ينتج البناء موقعًا ثابتًا في `out/`. في Cloudflare Pages اضبط Node على 24، وأمر البناء `npm run build`، ومجلد النشر `out`. احتفظ بالإعداد `NEXT_PUBLIC_DATA_MODE=demo` لمعاينة البيانات التوضيحية. [دليل النشر](https://developers.cloudflare.com/pages/framework-guides/nextjs/deploy-a-static-nextjs-site/)

## الانتقال إلى دخول حقيقي

استخدم مشروع Supabase مستقلًا للتجربة. طبّق ملف SQL الموجود في [المخطط](supabase/migrations/202611190001_newsroom.sql) كترحيل. اترك مخطط `newsroom` داخليًا، وأتح الدوال المقصودة في `public` للـData API. أنشئ حسابَي تجربة في Supabase Auth واربط كل مستخدم بجهته في `newsroom.members`. صلاحيات الإنشاء وإسناد الأدوار تخص مسؤول قاعدة البيانات.

لتحميل الأمثلة في بيئة تجربة جديدة يولّد الأمر التالي SQL محليًا. راجعه ثم طبّقه على قاعدة التجربة وحدها. اضبط خيار تأكيد البريد أو أنشئ مستخدمين مؤكدين للاختبار من لوحة Supabase.

```sh
node scripts/fixture-sql.mjs > /tmp/kashida-staging-seed.sql
```

```sql
-- استبدل المعرف الأول بمعرف حقيقي من Auth. المعرّف الثاني لجهة مزيد في عينة التجربة.
insert into newsroom.members(user_id, org_id, role)
values ('<auth-user-uuid>'::uuid, '10000000-0000-4000-9000-000000000001', 'editor');
```

معرّف رصد في العينة ينتهي بـ `0002`. يستطيع مستخدم من دور `platform_admin` بعضوية `org_id = NULL` إدارة متابعات الجهات من الواجهة. إدارة الاشتراكات التجارية وسجل الاستهلاك مرحلة لاحقة.

اضبط `NEXT_PUBLIC_DATA_MODE=supabase` و`NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` وقت البناء، ثم أعد بناء الواجهة. المفتاح المستخدم هنا من نوع Publishable. مكان مفاتيح الجمع المستقبلية هو أسرار الخادم. [دخول Supabase](https://supabase.com/docs/reference/javascript/auth-signinwithpassword) · [سياسات الرؤية](https://supabase.com/docs/guides/database/postgres/row-level-security)
